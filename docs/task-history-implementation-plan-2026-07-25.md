# 历史任务显示与查阅实施计划

日期：2026-07-25

状态：已完成

目标版本：首个只读历史任务版本

## 1. 目标

在不干扰当前 Agent 状态机运行的前提下，为桌面端增加历史任务入口，使用户能够：

1. 按最近更新时间查看已经写入 SQLite 的任务。
2. 查看某个任务的最新状态快照、阶段、计划修订号和资源进度。
3. 查阅任务日志、工具执行结果、审批记录和工作区导出记录。
4. 手动刷新历史任务，看到刚刚持久化的任务状态。

## 2. 首版范围

### 包含

- 侧边栏新增“历史”入口。
- 历史任务列表，默认按 `updated_at` 倒序排列。
- 历史任务详情：
  - 任务名称、任务 ID、当前阶段、计划修订号和更新时间。
  - 资源数量、已验证资源数量和工作区准备状态。
  - 当前最新状态快照中的资源、运行日志、模型决策和工具结果。
  - 该任务保存的全部审批记录。
  - 该任务保存的全部工作区导出记录。
- 加载中、空列表、读取失败和详情不存在等状态。
- SQLite 查询、IPC 参数校验和渲染层返回值校验。

### 不包含

- 删除、清空、归档历史任务。
- 从历史记录恢复或切换当前 Agent 运行状态。
- 修改历史任务的数据。
- 保存同一任务每次状态变化的完整事件流。
- 跨设备同步、云端存储或多用户隔离。

这些能力会改变当前运行状态或涉及数据生命周期，应在只读功能稳定后单独设计。

## 3. 数据基础与约束

当前 `task_snapshots` 表已经按 `task_id` 保存每个任务的最新快照，因此首版不需要新增表或升级 SQLite schema，数据库版本继续保持 v1。

历史任务在首版中的定义是“每个任务的最新持久化快照”，不是任务每一次修订的完整快照历史。审批和工作区导出表按修订号保留记录，因此详情页可以展示这些修订记录。

查询必须满足以下约束：

- 只读，不更新任务状态和审批状态。
- 列表限制为最多 100 条，默认返回最近 50 条。
- 无效 task ID、非法 limit 和损坏的持久化状态不得进入渲染层。
- 数据库错误通过结构化错误码返回，不向渲染层暴露文件路径或 SQL 细节。

## 4. 技术方案

### 4.1 TaskStore

新增两个公开查询：

- `listTaskHistory(limit)`：返回轻量摘要，不把每条完整状态发送到列表页。
- `getTaskHistoryDetail(taskId)`：返回指定任务的最新状态、审批记录和工作区导出记录。

摘要字段包括：

- `taskId`
- `task`
- `phase`
- `revision`
- `approvedRevision`
- `updatedAt`
- `resourceCount`
- `verifiedResourceCount`
- `workspaceReady`
- `hasErrors`

详情字段包括：

- `summary`
- `state`
- `approvals`
- `workspaceExports`

### 4.2 主进程与安全 IPC

新增：

- `agent:listTaskHistory`
- `agent:getTaskHistoryDetail`

主进程负责：

- 校验 limit 范围和 task ID 格式。
- 调用 TaskStore。
- 将异常转换为稳定的历史任务错误码。

preload 只暴露上述两个明确方法，不暴露通用 SQL、数据库路径或任意 IPC 调用能力。

### 4.3 渲染层

新增独立的历史任务状态 Hook，职责包括：

- 进入历史页面时刷新列表。
- 自动选择最近的一条任务并读取详情。
- 切换任务时处理并发请求，避免旧响应覆盖新选择。
- 验证详情中的状态快照结构。
- 向页面提供刷新、选择、加载和错误状态。

历史任务页面采用列表与详情双栏布局；窄窗口下改为纵向排列。页面为只读，不提供会影响当前状态机的操作。

### 4.4 与 Agent 状态机的关系

历史查询旁路当前 `useAgentCore` 运行状态：

- 不调用 `restoreTask`。
- 不改变当前 phase、revision 或 approval。
- 不触发模型请求、工具调用或持久化写入。
- 当前任务继续按原状态机运行。

## 5. 实施顺序

1. 增加 TaskStore 摘要与详情查询。
2. 增加主进程 IPC、preload bridge 和渲染层类型声明。
3. 增加历史任务 Hook。
4. 增加侧边栏入口和历史任务列表/详情页面。
5. 增加样式与响应式布局。
6. 补充持久化、组件、Electron 渲染和端到端测试。
7. 更新 README 中的功能说明与 SQLite 数据说明。
8. 运行完整 CI 验证并审计工作区改动。

## 6. 测试计划

### TaskStore 持久化测试

- 多个任务按更新时间倒序返回。
- limit 生效且非法范围被拒绝。
- 摘要中的资源、错误和工作区状态正确。
- 详情返回正确的最新状态、审批和导出记录。
- 不存在的 task ID 返回 `null`。
- 损坏的状态快照不会作为有效历史任务返回。

### 渲染层与组件测试

- 加载、空列表、错误和正常数据状态。
- 选中任务的详情正确显示。
- 资源、审批、日志和导出信息正确显示。
- 详情不存在或格式无效时有明确提示。

### Electron 验证

- preload 只暴露限定的历史查询接口。
- 历史导航可以打开列表并切换详情。
- 真实 SQLite 中已持久化的任务可在历史页面查阅。
- 查看历史不会改变当前任务状态。

### 回归验证

- TypeScript 类型检查。
- ESLint。
- Vitest 单元测试及覆盖率门槛。
- 持久化验证脚本。
- Electron 渲染验证。
- Playwright Electron E2E。

## 7. 完成标准

只有同时满足以下条件，首版才视为完成：

- 用户可以从侧边栏进入历史任务页面。
- 至少可以查阅任务列表和一条任务的完整只读详情。
- 列表、详情、空状态和错误状态均可用。
- 查询不会修改当前 Agent 状态机或 SQLite 数据。
- 所有新增接口均经过输入校验和结构验证。
- 新增测试通过，原有测试无回归，完整 CI 验证通过。

## 8. 后续候选能力

以下能力不在本次实现中，可在首版稳定后评估：

- 按状态、时间或关键词筛选。
- 任务归档与受控删除。
- 导出任务审计报告。
- 完整事件溯源和每次修订快照。
- 从历史任务创建一个新的重试任务，而不是覆盖当前状态。
